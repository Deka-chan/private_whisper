# Superwhisper-подобная диктовка — дизайн (v1)

- **Дата:** 2026-06-06
- **Статус:** утверждён к планированию
- **Имя продукта:** `privatewhisper` (имя крейта и бинарника; директория репозитория пока `superwhisper`, переименование каталога — по желанию)

## 1. Цель

Лёгкое нативное приложение для Windows: нажал глобальный хоткей → говоришь → нажал ещё раз → речь распознаётся локально на GPU (Parakeet TDT 0.6b v3) → текст автоматически вставляется по месту курсора в активном окне. Сам бинарник лёгкий; тяжёлый файл модели (~1.25 ГБ) докачивается при первом запуске.

## 2. Зафиксированные решения

| Параметр | Решение | Обоснование |
|---|---|---|
| Платформа v1 | **Только Windows** (RTX 5060) | Быстрый путь к рабочему инструменту; кроссплатформа — в архитектуре, не в реализации |
| Язык/стек | **Чистый Rust** | Лёгкий нативный exe, кроссплатформенные крейты на будущее |
| ASR-движок | **`parakeet-rs`** (поверх `ort`/ONNX Runtime) | Решает TDT-декодер за нас; умеет fp16 + CUDA/TensorRT; качает v3 с HF; авто-фолбэк на CPU |
| Модель | **Parakeet TDT 0.6b v3, FP16** | Мультиязык (25 языков, вкл. русский/украинский), автоопределение языка; fp16 реально грузит GPU |
| Точность/EP | **FP16 + CUDA EP**, фолбэк CPU | int8 на ONNX Runtime CUDA EP почти не ускоряется (нет ядер) — fp16 даёт Tensor Cores; так же делает Superwhisper |
| Режим хоткея | **Toggle** (нажал/нажал) | Удобно для фраз любой длины, не надо удерживать |
| Вставка текста | **Clipboard + Ctrl+V, авто, с restore** | «Как в Superwhisper»: вставка по курсору; надёжно для кириллицы/юникода |
| Источник модели | **HuggingFace** (репозитории, на которые ссылается parakeet-rs) | Для v3 fp16; точный манифест файлов уточняется в первом шаге плана |

## 3. Не-цели v1 (YAGNI)

Окно настроек (GUI); стриминг/частичные результаты; VAD; TensorRT-бэкенд; профили и несколько хоткеев; история диктовок; инсталлятор + подпись кода; сборки под Linux/macOS; кастомный словарь; int8-режим. Всё это закладывается архитектурно, но не реализуется в v1.

## 4. Архитектура

Одно нативное Rust-приложение: фоновый event-loop (`tao`) с треем и глобальным хоткеем; тяжёлое распознавание — на отдельном worker-потоке. Модули с одной ответственностью, общение через каналы (`mpsc`).

```
privatewhisper.exe  (tao event loop + tray + global hotkey)
│
├─ config   — чтение/запись config.toml, директории через `directories`
├─ model    — манифест модели, проверка наличия, докачка с прогрессом, верификация
├─ audio    — захват микрофона (cpal), буфер f32 + частота
├─ asr      — parakeet-rs: загрузка модели, CUDA→CPU fallback, transcribe
├─ inject   — вставка текста (clipboard + Ctrl+V) с сохранением/восстановлением буфера
└─ app      — стейт-машина Idle→Recording→Transcribing→Idle, оркестрация
```

**Принцип границ:** каждый модуль можно понять и протестировать отдельно. `asr`, `audio`, `model`, `inject`, `config` не знают про event-loop — они вызываются из `app` и общаются простыми типами (сэмплы, строки, пути, события прогресса). Это же даёт тестируемость без GPU/железа.

## 5. Поток данных и стейт-машина

```
[Старт]
  → load config
  → init tray + global hotkey
  → model.ensure()  (есть? иначе download+verify, прогресс в трее/уведомлении)
  → asr.load(provider=CUDA → при ошибке CPU)
  → IDLE

IDLE  --hotkey--> RECORDING        (старт cpal stream, иконка «запись»)
RECORDING --hotkey--> TRANSCRIBING (стоп stream → буфер воркеру)
TRANSCRIBING:
   asr.transcribe(samples, rate) → text
   text → trim/normalize
   inject(text): save clipboard → set text → SendInput(Ctrl+V) → ~80мс → restore
   → IDLE
```

Модель offline + режим toggle ⇒ записываем фразу целиком, затем распознаём. VAD/стриминг не нужны. Лимит длины аудио parakeet-rs (~4–5 мин) для диктовки несущественен.

## 6. Компоненты (детально)

### 6.1 `config`
- **Назначение:** загрузка/сохранение настроек.
- **Файл:** `%APPDATA%/privatewhisper/config.toml` (через `directories`).
- **Поля:** `hotkey` (строка, дефолт `Ctrl+Space`), `execution_provider` (`cuda`|`cpu`, дефолт `cuda`), `input_device` (опц., дефолт системный), `paste_delay_ms` (дефолт 80), `model_dir` (опц. override).
- **Поведение:** при отсутствии файла создаётся с дефолтами. Базовые переключатели (provider) дублируются в меню трея; смена применяется при рестарте.

### 6.2 `model`
- **Назначение:** гарантировать наличие файлов модели локально.
- **Хранилище:** `%LOCALAPPDATA%/privatewhisper/models/parakeet-v3-fp16/`.
- **Манифест:** список `{url, filename, expected_size, optional_sha256}`. Точный набор файлов и URL для parakeet-rs v3 fp16 **подтверждается в первом шаге плана** по README/примеру parakeet-rs (ожидаемо: `encoder-model.fp16.onnx` ~1.2 ГБ, `decoder_joint-model.fp16.onnx` ~35 МБ, `vocab.txt`, файл препроцессора/feature-extractor, `config.json`). Манифест вынесен в данные → легко править без изменения логики.
- **Докачка:** `reqwest` streaming, по файлам, суммарный прогресс (~1.25 ГБ); прогресс → tooltip трея + системное уведомление. Проверка размера (и sha256, если задан). Retry с backoff. При сбое — понятная ошибка + возможность положить файлы вручную в `model_dir`.
- **Идемпотентность:** уже существующие валидные файлы не перекачиваются.

### 6.3 `audio`
- **Назначение:** запись с микрофона.
- **Реализация:** `cpal`, дефолтное устройство ввода. Захват в нативном формате устройства → конвертация в `f32` mono; частота передаётся в `asr` как есть (parakeet-rs/препроцессор ресемплит при необходимости).
- **API:** `start() -> Stream`, накопление в общий буфер; `stop() -> (Vec<f32>, sample_rate)`.

### 6.4 `asr`
- **Назначение:** распознавание.
- **Реализация:** `parakeet-rs` (фича `cuda`). Загрузка: `Parakeet::from_pretrained(model_dir, ExecutionConfig::new().with_execution_provider(Cuda))`; при ошибке инициализации GPU — повтор с `Cpu` + уведомление «работаю на CPU (медленнее)».
- **API модуля:** `load(provider) -> Asr`, `transcribe(&self, samples: &[f32], rate: u32) -> Result<String>` (через `transcribe_samples`, берём `.text`).

### 6.5 `inject` (вставка как в Superwhisper)
- **Назначение:** автоматическая вставка текста по месту курсора.
- **Алгоритм (Windows):** сохранить текущий буфер обмена (`CF_UNICODETEXT`) → положить распознанный текст → `SendInput` Ctrl+V → подождать `paste_delay_ms` → восстановить прежний буфер.
- **Фолбэк:** если вставка не удалась (окно не приняло) — оставить текст в буфере + уведомление «скопировано».
- **Крейты:** `arboard`/`clipboard-win` (буфер), `enigo` или прямой `windows`-crate `SendInput`.

### 6.6 `app`
- **Назначение:** оркестрация, стейт-машина, обновление иконки/тултипа трея, обработка событий хоткея и прогресса.
- **Меню трея:** статус; Execution provider (CUDA/CPU); Re-download model; Open config; Quit.

## 7. Модель конкурентности

- Event-loop (`tao`) держит трей и хоткей, не блокируется.
- Тяжёлые операции (загрузка модели в `asr`, докачка, распознавание) — на worker-потоке.
- Связь: `app` → worker команды и worker → `app` события прогресса/результата через `mpsc`; обновление трея — в event-loop через user-events.

## 8. Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Нет микрофона / ошибка устройства | Уведомление, остаёмся в Idle |
| GPU init не удался (sm_120/драйвер) | Авто-фолбэк на CPU EP + уведомление |
| Модель не докачалась | Уведомление + retry + опция ручной установки |
| Пустой результат распознавания | No-op (тихо вернуться в Idle) |
| Окно не приняло вставку | Текст остаётся в буфере + уведомление «скопировано» |

## 9. Тестирование

- **Unit:** парсинг/запись config; детект наличия файлов модели по манифесту; конвертация аудиобуфера (i16/f32, каналы); нормализация текста.
- **Integration (кроссплатформенно, CPU EP, без GPU):** прогон эталонного WAV через `asr` на CPU → ассерт на непустой/ожидаемый текст. Гоняется на Linux/WSL2 dev-машине и в CI без видеокарты.
- **Ручной чек-лист (Windows + RTX 5060):** первый запуск → докачка модели с прогрессом; хоткей-toggle → речь (рус/англ) → авто-вставка в Notepad/браузер; проверка, что GPU задействован (диспетчер задач/`nvidia-smi`) и латентность приемлема; проверка CPU-фолбэка (форс `provider=cpu`).

## 10. Риски и ранние spike'и

1. **Blackwell / sm_120 (главный риск):** RTX 50-й серии требует свежего onnxruntime с CUDA 12.x. **Spike в первую очередь:** собрать минимальный пример parakeet-rs с `cuda`, загрузить fp16-модель, распознать тестовый WAV на RTX 5060. Если GPU не стартует — зафиксировать требуемую версию ORT/CUDA; CPU-фолбэк как страховка.
2. **Точный манифест модели для parakeet-rs v3 fp16:** подтвердить набор файлов и HF-URL по README/примеру крейта до реализации `model`.
3. **Зрелость parakeet-rs:** новый крейт — проверить end-to-end (загрузка + распознавание + язык) на раннем этапе.
4. **UX докачки ~1.25 ГБ:** внятный прогресс, обработка обрыва сети, докачка/повтор.
5. **Сборка с CUDA на Windows:** нужны onnxruntime-CUDA + cuDNN; полагаемся на загрузку бинарников `ort`/feature crate, иначе документируем установку.

## 12. К уточнению на этапе плана
